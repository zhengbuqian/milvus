# Index simplification implementation plan

**Goal:** Implement the accepted code and structural simplifications in the 2026-09-09 architecture review, revision 3, without changing index algorithms, persisted formats, ownership, or publication semantics.

**Architecture:** Remove unused abstraction layers and consolidate genuinely shared operations. Preserve family-specific serialization, unique reader ownership behind pins, and the existing growing protocol. This is an auxiliary refactoring plan, not a production-code dependency.

**Tech stack:** C++20, Go/cgo, existing cachinglayer and storage APIs.

- Consumers receive borrowed reader interfaces protected by pins, never shared reader ownership. Internal dependency owners may be shared.
- HybridIndexArtifact and JsonProjectedIndexArtifact remain distinct family wrappers. Preserve selector encoding, all generation-specific metadata, and presence/absence rules for empty and non-empty sidecars.
- Preserve vector physical-type and dense/sparse dispatch, algorithms, fixed pin prefixes/mappings and deferred lifetimes; old-pin ANN hits may change with the live engine.
- Preserve pre-load versus post-load resource accounting, including V1 vector's zero admission and post-load estimate.

- Reopen privately backfills new owners, flushes, registers, and publishes schema. It does not enter the ordinary pending queue or advance the main ACK.
- Do not change SegmentLocal identity representation/allocation, switch sealed Tantivy reload policy, make inventory the sole state source, migrate growing exact-key selection, or merge all FileSource implementations into a final class. Those are separate follow-ups.
